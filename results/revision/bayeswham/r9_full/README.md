# R9 BayesWHAM inputs

`raw_counts/` contains the full 25-window R9 dataset converted to the text
interface expected by BayesWHAM. Inputs use the same 40,000-frame equilibration
removal as the manuscript ablation and a common grid whose centers match the
existing WHAM reference (1.45--5.40 nm at 0.05 nm spacing).

The spring center and force constant for every window are read directly from
its `step7_production.mdp` file. The system temperature is validated as
303.15 K, and the coordinate is nonperiodic.

These files contain raw histogram counts. They are intended first for checking
the BayesWHAM MAP surface against the conventional WHAM reference. Because the
saved trajectory frames are temporally correlated, these raw counts must not
be used for the final uncertainty comparison without an explicitly documented
autocorrelation treatment.

`effective_counts_ar1/` contains the corresponding uncertainty-analysis input.
For each window, every raw bin count is divided by the AR(1) autocorrelation
time estimated from its retained coordinate trajectory using
`freegp.preprocess.bayes_autocorrelation_time`. This preserves the observed
per-window histogram probabilities while reducing the window's total
likelihood weight to its estimated effective sample size. The individual
autocorrelation times and effective counts are recorded in `manifest.json`.

Regenerate the inputs from the active repository root with:

```bash
source .venv/bin/activate
python results/revision/bayeswham/prepare_r9_inputs.py
```

The uniform-prior BayesWHAM MAP validation for the AR(1) effective-count input
is stored under `map_validation/effective_counts/`. Its dimensionless
`betaF_MAP.txt` is converted to kJ/mol at 303.15 K and maximum-aligned with the
paper WHAM reference by `../plot_r9_map_validation.py`.

For production UQ, the same BayesWHAM posterior and uniform simplex prior are
sampled with four modern NUTS chains by `../run_r9_bayeswham_nuts.py`. This
replaces only the original slow one-bin Metropolis sampler, not the probability
model. Posterior samples and diagnostics are stored under `uq/nuts/`; the
comparison with the archived full-data hierarchical GP is generated by
`../plot_r9_uq_comparison.py` under `uq/comparison/`.
