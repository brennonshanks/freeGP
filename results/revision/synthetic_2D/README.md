# Synthetic 2D Umbrella-Sampling Tutorial

This tutorial creates a small two-dimensional umbrella-sampling dataset from a
known free-energy surface and reconstructs it with freeGP's multidimensional
GP (`freegp.gp.build_joint_gp_nd`). It is the 2D analogue of
`tutorials/synthetic_umbrella`.

The synthetic target surface is a double well in `u = x + y` crossed with a
harmonic well in `v = x - y`:

$
U(x,y) = a\left(\tfrac{1}{2}(x+y)^2 - b^2\right)^2 + \tfrac{c}{2}(x-y)^2,
\qquad a=4,\ b=3,\ c=50.
$

For each umbrella window centered at \((x_0, y_0)\), the script samples
positions from

$
p_i(x,y) \propto \exp\!\left[-\left(U(x,y) + \tfrac{1}{2}\kappa\left((x-x_0)^2 + (y-y_0)^2\right)\right)\right]
$

using a random-walk Metropolis-Hastings sampler (no molecular dynamics
software required). The generated files use a flat 2D dataset format:

The synthetic sampler uses reduced units with $kT=1$. During reconstruction,
the analytic reference energies and umbrella force constants are both
multiplied by $k_BT$ at 303.15 K so that they follow freeGP's internal kJ/mol
energy convention. The sampled coordinates are unchanged by this conversion.

```text
example_data/
  README                 # window_id, x0, y0, isotropic force constant
  w00-xyplane.xvg
  w01-xyplane.xvg
  ...
  ground_truth.csv       # exact synthetic reference surface, on a regular (x, y) grid
```

## Run

From this directory:

```bash
python make_dataset.py
python run_2D_reconstruction.py
```

Outputs are written to:

```text
tutorial_results/
  synthetic_2D_reconstruction.png
  synthetic_2D_reconstruction.csv
```

The default run compares:

- the known reference surface
- a fixed-hyperparameter GP
- a MAP hierarchical GP using the LOO objective and default hyperpriors
- a HMC-NUTS hyperposterior-propagated GP

Each umbrella window contributes histogram-derived free-energy estimates
(function observations) plus one 2D gradient ("restoring force") estimate at
its center (derivative observations), exactly as in the 1D tutorial, but with
the derivative observation now being the full 2D gradient rather than a
scalar. See `freegp.gp.build_joint_gp_nd` for the underlying kernel math.

To skip HMC and run only the fixed and MAP reconstructions:

```bash
python run_2D_reconstruction.py --skip-hmc
```

### A note on HMC runtime and warm-starting

Every HMC-NUTS leapfrog step needs a fresh Cholesky factorization (and its
gradient) of the joint covariance matrix, whose size scales with
`n_windows * num_bins**2 + n_windows * 2`. That is far more expensive per
iteration than the single-Cholesky-per-optimizer-step MAP fit above, so the
script's HMC defaults (`--warmup-steps 10 --num-samples 10
--predictive-samples 10 --num-chains 1 --max-tree-depth 5`) are deliberately
small -- enough to get a real (if noisy) hyperposterior spread, not
publication-quality uncertainties. On the bundled `example_data`, the full
default run (fixed + MAP + HMC) takes about 4 minutes.

Hierarchical GP hyperparameter posteriors like this one can have a spurious
short-lengthscale/high-noise local mode: once the kernel's length scale drops
below the spacing between observations, the model can "explain" the data as
pure per-point noise instead of a smooth surface, and with only a handful of
warmup iterations an arbitrarily-initialized chain may get stuck there rather
than at the physically meaningful mode. To avoid this, the script warm-starts
every HMC chain at the MAP estimate it already computed (see
`freegp.hmc.run_hmc_nuts`'s `init_params` argument) rather than relying on
Pyro's default initialization -- this alone was enough to keep `ell` near the
MAP value across sampling instead of collapsing towards zero. If you still see
a degenerate HMC surface (uncorrelated per-bin noise instead of a smooth
reconstruction), that is the failure mode to suspect; check the sampled `ell`
values first.

For a more trustworthy (but much slower) run, increase the sample counts,
e.g.:

```bash
python run_2D_reconstruction.py \
  --warmup-steps 100 \
  --num-samples 200 \
  --predictive-samples 50 \
  --num-chains 1
```

If that is too slow, reduce `--num-bins` (fewer histogram bins per window
shrinks the joint covariance matrix, at the cost of spatial resolution
within each window) before increasing the HMC sample counts.

## Trying Your Own Data

Point the script at a compatible dataset with:

```bash
python run_2D_reconstruction.py \
  --dataset-root /path/to/my_dataset \
  --reference-path /path/to/ground_truth.csv
```

The reference path is optional and is used only for plotting/comparison.

## Notes

- `example_data/` as generated by `make_dataset.py` has 100 windows on a
  10x10 grid; `--num-bins` controls the per-dimension histogram resolution
  used for the function-value observations within each window. Since the
  joint GP scales cubically with `n_windows * num_bins**2 + n_windows * 2`,
  keep `--num-bins` modest (the default is 5) unless you thin the window grid.
- The nonstationary Gibbs kernel (available in the 1D tutorial) is not
  extended to multidimensional data; only the stationary SE kernel is
  supported here, for fixed, MAP, and HMC-NUTS reconstructions alike.
- For real analyses, increase `--opt-steps`/`--opt-restarts` and check that
  the MAP fit is not sensitive to the optimizer seed. Do the same for the
  HMC settings -- see the runtime note above.
